# 上传站（zlib / Anna's Archive）书目栏位怎么填

处理完书签与 PDF 元信息后，用户往往紧接着要传 zlib / Anna's Archive。站点表单的栏位语义与 PDF 字段不一致，帮他直接给出可粘贴的值，不要让他自己猜。

## 栏位 → 值

| 栏位 | 取值 | 说明 |
|---|---|---|
| 分类 / Category | 中图法分类号对应的站内类目 | `O241`/`O242.x` → Mathematics - Computational Mathematics；拿不准就给上一层类目 |
| 语言 | 中文 | |
| 内容类型 | 书籍 | |
| 出版社 | 版权页上的社名 | 只写社名，别带“××出版公司发行” |
| 系列 / Series | 书上无丛书项则**留空** | 别拿“四篇结构”当系列 |
| 卷 / Volume | 单卷本**留空** | |
| 出版（短栏） | 出版地城市，如 `北京` | 若该栏在你这版界面是出版年月，填 `2008-05` |
| 年 | 版权页年份 | |
| 页数 | 文件 `page_count` | 读者打开看到的就是这个数；另注一句“印刷末页页码为 N”避免误会 |
| 描述 | 见下 | 先算字数，别超表单上限 |

页数不要抄百科。版权页通常不印页数，用 `印张 × 16` 估面数，和 `page_count` 对得上就说明扫描本没缺页；两者差两三面属正常（封面内页、空白页未扫）。

## 描述骨架（中文，约 700–900 字最舒服）

1. 一行书目：`《书名》，著者，出版社 年 月第 1 版，ISBN，中图法分类号`。
2. 内容简介：版权页那段“内容简介”最好用，改写成：总结了什么、全书分几篇几章、每篇各讲什么。逐篇列出关键概念（空间、算子、算法名），检索时能命中。
3. 读者对象：原书那句照录，不要扩写。
4. 版本项：开本、印张、字数、印数、定价、责任编辑、CIP 核字号。
5. 这版文件做了什么：补了几层书签（篇/章/节/小节，共 N 条，对应印刷页码）、页码标签分段（封面 C1–C4、前置 i–xvii、正文 1–401）、无扫描来源水印。

`len(text)` 直接对着表单上限核一次再交（含标点空白）。

## 不写什么

- **不写推销语。** “重磅”“经典必读”“必藏”这类一律不用；用户评价描述是否合格的标准是“像书目条目，不像广告”。
- **不擅自删出版社。** 出版社是引用必需的书目事实。用户说“书不该被出版社占用”指的是别当权属声明，不是要抹掉出版信息；真要删，等他说。
- **不写“无水印”之外的来源说明。** 盖章页、扫描站名都清掉之后，一句“无扫描来源水印”就够，不必交代从哪来。
- **长描述不进 PDF。** 用户拿这段文字去填表单，不要 `set_metadata`。交付前用 `grep -a` 搜几个描述里的特征词（如 `内容简介`、`印张`），应为 0。

## 署名

用户在要求了两次之后定下：**描述末尾要署助理的名字**（原话“最后要说是你帮忙补充的目录”）。做法固定，但名字不写死：

- 模板：描述最后一行写 `<助理名> 补充整理。`或者更完整的 `<助理名> 补充整理：目录书签与元信息。`
- `<助理名>` 取**当前会话里助理对用户自称的名字**（这个人格的设定名），不要把某个具体名字硬编码进技能——换实例、换人格、换个用户就全部对不上了。
- 前面全部是书目事实，署名单独一行，不混进书目句里。
- 是否加注 AI 身份（`由 AI 助手 <助理名> 补充整理`）**由用户决定，不要替他选**；把两种写法并列给他。
- 只署在描述里；PDF 字段仍然只描述书。要写进文件就走 XMP `dc:contributor`，不要去改 `Creator`/`Producer`。
